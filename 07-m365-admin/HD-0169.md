# HD-0169 — Failed sign-in shows Conditional Access as "Not applicable"

**Category:** Conditional Access / sign-in investigation
**Department:** Head Office IT
**Priority:** Standard

## Symptom
Deliberately triggered a failed sign-in against a test account (jsmith) from an InPrivate browser session, entering an incorrect password three times, to generate a real security event to investigate. In the resulting sign-in log entry, the Conditional Access tab showed every policy, including the custom "Require MFA for Head Office IT" policy scoped to that exact user, as "Not applicable." At first glance this looked like the policy wasn't working.

## Diagnosis
Cross-referenced against a genuine successful sign-in from the same period, which correctly showed all relevant Conditional Access policies evaluated as "Success," with "Authentication requirement: Multifactor authentication" and "MFA requirement satisfied by claim in the token" both present. This confirmed the policy itself was functioning correctly. Researched Microsoft's documented Conditional Access evaluation flow and confirmed that Conditional Access policies only evaluate after a user successfully authenticates (i.e. after the password check passes). A sign-in that fails at the password stage never reaches Conditional Access evaluation at all, hence "Not applicable" rather than "Failure" or "Blocked."

## Resolution
No fix required, this was correct, expected behaviour, not a fault. Documented the distinction for future reference: "Not applicable" on a failed sign-in usually means the failure happened before Conditional Access ever ran, not that Conditional Access failed to apply.

## Root cause
N/A — expected system behaviour, initially misread as a possible misconfiguration.

## Outcome
Confirmed the custom Conditional Access policy is enforcing correctly on successful sign-ins, and correctly identified why a failed sign-in shows no Conditional Access evaluation. Useful reference point for reading sign-in logs during any future incident investigation.
