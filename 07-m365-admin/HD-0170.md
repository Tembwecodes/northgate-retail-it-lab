# HD-0170 — Risky sign-ins report shows no results for known failed logins

**Category:** Identity Protection / licensing boundary
**Department:** Head Office IT
**Priority:** Low

## Symptom
After generating deliberate failed sign-in attempts (see HD-0169) and confirming they appeared correctly in the standard sign-in log, checked the Risky sign-ins report expecting the same events to appear there for risk-based investigation. The report returned no results.

## Diagnosis
Reviewed how Microsoft Entra ID Protection's risk detection engine works: it flags sign-ins based on anomaly signals such as impossible travel, sign-ins from anonymous IP addresses, or leaked credential matches, not simply repeated failed password attempts from a consistent, known IP address. Cross-checked against the tenant's Identity Secure Score, which separately and explicitly listed "Protect all users with a sign-in risk policy" as a High-priority recommendation requiring Microsoft Entra ID P2, a licence tier this E3 tenant does not have.

## Resolution
No fix applicable, this is a licensing boundary, not a fault. Confirmed the absence of results is the correct, expected outcome for this scenario under an E3 licence, rather than evidence that logging or investigation had failed.

## Root cause
Feature gated behind Entra ID P2 licensing (Identity Protection's risk-based detection), not present in this tenant's E3 subscription.

## Outcome
Documented as a genuine, honest scope boundary in the project writeup rather than presented as a completed capability. Demonstrates the ability to correctly diagnose a licensing limitation rather than assume a configuration fault.
