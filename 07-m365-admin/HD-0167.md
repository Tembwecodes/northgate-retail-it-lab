# HD-0167 — Azure AD Connect fails at application-based authentication step

**Category:** Hybrid identity / directory sync
**Department:** Head Office IT
**Priority:** High (blocking)

## Symptom
Microsoft Entra Connect Sync install progressed successfully through directory connection and OU filtering configuration (scoped to the four department OUs), but failed at the final "Configure" step with: "Microsoft Entra Connect could not configure application-based authentication for this server."

## Diagnosis
Reviewed the Entra Connect installation log and traced the failure to an MSAL `AcquireTokenWithCertificate` error. Retried the configuration step cleanly with no change. Researched the error and identified it as consistent with Microsoft's newer mandatory Application-Based Authentication feature failing its software-certificate fallback, a known friction point in environments without a TPM, which a nested VirtualBox VM (Windows Server 2022 running inside VirtualBox, itself on a physical host) does not expose.

## Resolution
Rather than continue troubleshooting a certificate/TPM limitation specific to this nested virtualisation setup, and unrelated to the actual M365 administration skills the project was meant to demonstrate, made the decision to stop pursuing the hybrid sync and rescope the remaining project to a cloud-only Microsoft 365 administration lab.

## Root cause
Environment limitation (no TPM available to a nested VM), not a configuration or procedural error.

## Outcome
Hybrid identity sync abandoned as a documented, deliberate scope decision. Project rebuilt as a cloud-only M365 admin lab (12 cloud-only users, Exchange, Teams, SharePoint, Conditional Access, admin tasks), which still covers the CV-relevant M365 administration ground without requiring a working AD Connect sync.
