HD-0152: Finance File "Missing" Due to Search Indexing Lag on Fresh VM
Category: Finance Priority: Standard Status: Resolved

Summary
A Finance user reported a moved/renamed file as missing. Windows Search returned nothing for it even though the file's content was confirmed correct, tracked down to search indexing not having caught up yet on the freshly built VM, and recovered by sorting on file metadata instead of relying on content search.

Problem
Simulated a file being moved and renamed on Win11-Client for a Finance user. Searching for the file by its known content ("budget") turned up nothing in Windows Search, even though the file definitely existed somewhere in Documents. Needed to connect remotely, locate the file, and confirm it was recoverable.

Discovery
Connected to Win11-Client over TeamViewer. Ran a content search for "budget" in Windows Search, no results, despite manually confirming the file was present and its contents were correct once located another way.

Recognised this as an indexing problem rather than a missing-file problem, Windows' search index hadn't caught up on the freshly built VM, so content search couldn't find something that was genuinely there.

Fix
Rather than wait on or force a reindex, worked around it directly, opened Documents and sorted by Date Modified (descending) across subfolders. The renamed file surfaced immediately near the top of the list, since it had been the most recently touched file regardless of what it had been renamed to.

Verification
Opened the file from its correct location to confirm the content matched what the Finance user expected, then confirmed with the "user" that the file was accessible again from its new name and location.

Root Cause
Windows Search's content index on Win11-Client hadn't finished cataloguing the file system, a normal state for a freshly built VM rather than a fault, meaning content-based search couldn't locate a file that existed and was otherwise fine.

Resolution
* Confirmed the file existed and its content was correct, ruling out actual data loss
* Diagnosed the failed content search as an indexing lag rather than a missing file
* Recovered the file by sorting Documents by Date Modified instead of relying on content search
* Confirmed with the end user that the file was accessible again

Lessons Learned
* Don't rely on Windows Search content indexing on a freshly built VM, the index needs time to catch up and will return false negatives in the meantime
* Sorting by Date Modified is a reliable first move for a "missing" file that's more likely moved or renamed than actually lost
* A failed search isn't proof a file is gone, worth ruling out indexing/metadata issues before treating it as data loss
