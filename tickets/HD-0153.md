HD-0153: Wrong Default Printer After Adding a Second Printer for HR User
Category: Human Resources Priority: Standard Status: Resolved

Summary
A Human Resources user's default printer changed unexpectedly after a second printer was added to their machine. Traced to Windows' "manage my default printer automatically" setting, restored the correct default and switched off auto-management so the same issue wouldn't recur on its own.

Problem
Added a second (PCL6) printer to Win11-Client for an HR user, after which the wrong printer was set as default, print jobs weren't going where the user expected. Needed to connect remotely, fix the default, and stop it happening again.

Discovery
Connected to Win11-Client over TeamViewer. Checked Printers & Scanners and found "Let Windows manage my default printer" was enabled, expected this to auto-switch the default to whichever printer was last used, printing a test page didn't trigger that switch on its own the way expected.

To reliably reproduce the reported fault, manually set the wrong printer as default rather than relying on the auto-management behaviour to misfire on cue.

Fix
Set the correct printer (HR-Floor2-Printer) as the default manually through Printers & Scanners.

Turned off "Let Windows manage my default printer" afterwards, since leaving it enabled was the underlying reason the default could drift again the next time a printer was added or used, not something that needed to happen for this fix to hold, but needed to stop it recurring unprompted.

Verification
Confirmed via Printers & Scanners that HR-Floor2-Printer showed as the Default printer, and that auto-management was switched off. Printed a test page to confirm it routed to the correct printer.

Root Cause
Windows' automatic default-printer management doesn't behave predictably when a second printer is added, it can leave the wrong printer set as default rather than reliably switching to the most recently used one, and will keep influencing the default going forward unless disabled.

Resolution
* Identified "manage my default printer automatically" as enabled and the likely source of the wrong default
* Manually set HR-Floor2-Printer as the correct default
* Disabled automatic default-printer management to prevent recurrence
* Confirmed the fix with a test print routed to the correct printer

Lessons Learned
* Adding a second printer is a common trigger for default-printer issues when Windows' auto-management is left on
* Auto-management doesn't reliably switch to the last-used printer, don't assume printing a test page will trigger it
* Turning off auto-management should be a standard step when configuring a second printer, not something discovered only after a user reports the side effect
