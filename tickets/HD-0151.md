HD-0151: Display Resolution and Scaling Broken After Simulated Monitor Swap
Category: Head Office IT Priority: Standard Status: Resolved

Summary
A Head Office IT user's display resolution and scaling came out wrong after a simulated monitor swap. Connected remotely via TeamViewer to diagnose, found the root cause was a generic display driver with no better option available in the lab environment, and restored the one setting that could actually be fixed.

Problem
Simulated a monitor swap on Win11-Client and the resulting resolution and scaling were wrong for the "new" screen, text and UI elements were the wrong size and the display didn't look right. Needed to connect as the technician and get the display back to a usable state.

Discovery
Connected to Win11-Client over the existing TeamViewer session. The resolution dropdown in Settings > Display was locked and couldn't be changed directly while connected remotely, so the fix wasn't as simple as picking a different value from the list.

Checked Advanced Display settings and found Win11-Client was running the generic Microsoft Basic Display Adapter rather than a proper GPU driver, explaining both the locked resolution options and the poor scaling behaviour.

Fix
Checked Windows Update for a better driver, confirming none was available, this is expected in an isolated lab VM with no internet route to Microsoft's driver catalogue and no virtual GPU passthrough configured. Rather than force a workaround that wasn't genuinely available, documented it as a real driver/hardware limitation.

With the resolution itself off the table, restored the one display setting that was fixable, scaling, back to the recommended 125% for the display.

Verification
Confirmed via Settings > Display that scaling matched the recommended value and the UI rendered at a usable size again. Resolution remained fixed by the driver's limited option set, consistent with the Basic Display Adapter being in use, not a fault that was missed.

Root Cause
Win11-Client has no proper display driver installed, generic Microsoft Basic Display Adapter only, so the OS can't offer the full resolution range a real monitor and GPU combination would support, and Windows Update has no better driver to offer in this isolated environment.

Resolution
* Diagnosed the locked resolution dropdown as a driver limitation via Advanced Display settings, not a settings-level fault
* Confirmed via Windows Update that no improved driver was available in the isolated lab environment
* Restored scaling to the recommended 125%, the one setting that was genuinely fixable
* Documented the resolution limitation as a known constraint rather than reporting a false fix

Lessons Learned
* When a setting appears locked, check the underlying driver before assuming it's a permissions or session issue
* Not every ticket has a full fix available, recognising and documenting a genuine hardware/driver limitation is more honest and more useful than forcing a workaround that doesn't hold
* Isolated lab VMs default to generic display drivers with no internet route to fetch better ones, worth factoring into any display-related scenario built on this setup
