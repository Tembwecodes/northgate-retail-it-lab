HD-0154: No Internet Access, DHCP Lease Not Renewing
Category: Desktop Support Priority: Standard Status: Resolved

Summary
Win11-TroubleshootVM lost internet access with no obvious cause. Diagnosed as a stalled DHCP lease rather than a network hardware or driver fault, resolved with a release/renew cycle.

Problem
Simulated a "no internet" fault on Win11-TroubleshootVM, a standalone workgroup machine set up specifically for Tier 1/2 troubleshooting scenarios. The machine showed no network connectivity, with no other symptoms to go on initially.

Discovery
Checked basic connectivity first via ipconfig, the adapter had no valid IPv4 address, sitting on an APIPA (169.254.x.x) address instead of a proper lease from the network. This pointed to a DHCP issue rather than a cable/adapter/driver problem.

Fix
Ran a manual release and renew cycle:

ipconfig /release
ipconfig /renew

The adapter picked up a valid IP address from DHCP on the renew.

Verification
Confirmed via ipconfig /all that the adapter now held a proper IPv4 address in the expected range, then confirmed internet access was restored by reaching an external address.

Root Cause
The DHCP lease had stalled or expired without the adapter successfully renewing it automatically, leaving the machine on a self-assigned APIPA address with no route out.

Resolution
* Diagnosed the fault via ipconfig, confirming an APIPA address rather than a valid DHCP lease
* Ran ipconfig /release followed by ipconfig /renew to force a fresh lease
* Confirmed internet access restored

Lessons Learned
* An APIPA (169.254.x.x) address is the fastest visual confirmation that DHCP, not the adapter itself, is the problem
* A release/renew cycle is a quick first move for "no internet" before escalating to driver or hardware checks
