HD-0164: Windows Update Stuck, SoftwareDistribution Folder Corrupted
Category: Desktop Support Priority: Standard Status: Resolved

Summary
Windows Update on Win11-TroubleshootVM became unresponsive, with related update services failing to start. Traced to a corrupted SoftwareDistribution folder, fixed by clearing and restoring it in the correct service-stop order.

Problem
Simulated a Windows Update fault by stopping the Windows Update-related services (wuauserv, bits, cryptsvc) and replacing C:\Windows\SoftwareDistribution with a file instead of a folder. This reproduced two symptoms at once: the services failing to start again, and the "Check for updates" button in Settings becoming unresponsive.

Discovery
Attempted to restart the stopped services and they failed, checked Service Control Manager events and found errors indicating the SoftwareDistribution path couldn't be found as expected, consistent with a file existing where Windows expected a folder.

Fix
Worked through the standard SoftwareDistribution reset sequence in the correct order:

1. Stopped wuauserv, bits, and cryptsvc (where not already stopped)
2. Removed the broken file sitting at the SoftwareDistribution path
3. Restored the renamed-aside SoftwareDistribution folder back to its original name and location
4. Restarted cryptsvc, bits, and wuauserv in that order

Verification
Confirmed all three services started successfully and stayed running, then opened Settings and confirmed "Check for updates" responded normally and began checking rather than hanging.

Root Cause
The SoftwareDistribution folder, which Windows Update depends on for downloading and staging update files, had been replaced by a file at the same path, causing the dependent services to fail to start (since their expected working directory didn't exist as a folder) and the Update UI to hang waiting on those services.

Resolution
* Diagnosed the failed service starts via Service Control Manager event logs, confirming a path-not-found style error
* Removed the broken file occupying the SoftwareDistribution path
* Restored the correct SoftwareDistribution folder
* Restarted cryptsvc, bits, and wuauserv in the correct order and confirmed all started successfully
* Confirmed Windows Update responded normally afterward

Lessons Learned
* Windows Update service failures are worth checking against Service Control Manager events first, the exact error text usually points straight at the cause rather than requiring guesswork
* The SoftwareDistribution reset needs services stopped before removing/renaming the folder and restarted in the right order afterward (cryptsvc, bits, wuauserv), doing it out of order can leave services in an inconsistent state
