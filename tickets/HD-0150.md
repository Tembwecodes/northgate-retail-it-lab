HD-0150: 7-Zip Install Blocked by TeamViewer Download Redirect and Sign-In Gate
Category: Store Ops Priority: Standard Status: Resolved

Summary
Remote install of 7-Zip for a new Store Ops starter, connecting to Win11-Client over TeamViewer as the technician. The install itself was routine once connected, but getting a working remote session up at all took longer than expected, TeamViewer's own download page redirected away from the installer, and the free client hides the panel needed to start a session behind a sign-in wall.

Problem
A new Store Ops starter needed 7-Zip installed on their machine (Win11-Client) so they could open compressed files sent by suppliers. Needed to connect remotely as the technician, install the software, and confirm it was usable before closing the ticket.

Discovery
Went to download TeamViewer on the host side first. Clicking "Download" on TeamViewer's own page routed through Bing search results and into a Business trial signup / shopping cart flow rather than the actual installer, several clicks in before realising it wasn't heading anywhere useful.

Got the installer eventually and set it up on both the host (technician) and Win11-Client (end user), giving Win11-Client a second NAT network adapter alongside its existing intnet link to DC01 so it had an internet route without touching the domain connection.

Opened TeamViewer on the host expecting the classic "Control Remote Computer" panel with a Partner ID field, it wasn't there. The ID/password-only view doesn't expose that field until you're signed into a free account.

Fix
Skipped the marketing/search-result pages on a second attempt and went straight to the direct installer URL, which downloaded the actual client cleanly.

Signed into a free TeamViewer account on the host side, which unlocked the full connection panel. Connected to Win11-Client using the session code shown on that machine, with the simulated end user accepting the incoming connection request.

Verification
Once connected, installed 7-Zip on Win11-Client through the remote session, confirmed shell integration (right-click context menu options for archives appeared correctly), and pinned it to the taskbar so the "user" could find it easily going forward.

Root Cause
Two separate friction points rather than one fault: TeamViewer's download page funnels users through marketing/search flows instead of a direct link, and the free client's default ID/password view deliberately withholds the Partner ID field until sign-in, both are product behaviour rather than a lab misconfiguration.

Resolution
* Used the direct TeamViewer installer URL instead of following the download page's redirects
* Signed into a free TeamViewer account to unlock the full connection panel and Partner ID field
* Connected host to Win11-Client via session code, installed 7-Zip, confirmed shell integration and taskbar pin

Lessons Learned
* Go straight to a vendor's direct installer URL rather than clicking through their download page, marketing flows and search-result links can easily lead away from the actual installer
* Don't assume the ID/password-only view is the full feature set, sign in first if an expected panel or field is missing
* A second NAT adapter is enough to give an isolated lab VM an internet route for tools like TeamViewer without disturbing its existing domain-facing network
