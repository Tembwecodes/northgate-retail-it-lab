HD-0149: PowerShell Diagnostics Script Blocked by Missing Guest Additions
Category: Store Ops Priority: Standard Status: Resolved

Summary
Built a PowerShell script to automate a recurring set of Tier 1 checks (system info, network status, Print Spooler health, event log review) for Win11-Client. The script itself worked first time, but getting it onto the isolated lab VM did not, a VirtualBox shared folder wouldn't mount, which turned into its own troubleshooting task before the script could even be tested.

Problem
Store Ops raised a recurring pattern of tickets that all came down to the same handful of manual checks: is the network up, is the print spooler running, what's been showing up in the event log. Needed a script that automated all three in one pass and produced a log file that could be attached to a ticket as evidence, then needed to actually get that script running on Win11-Client to prove it worked.

Discovery
Wrote Northgate-Diagnostics.ps1 covering system info, network status (gateway and DNS), Print Spooler status with auto-restart, and a 24-hour System event log summary, each section wrapped in try/catch so one failed check wouldn't stop the rest, with everything logged to a timestamped file.

Win11-Client sits on an isolated lab network with no direct file transfer path from the host, so set up a VirtualBox shared folder pointing at a host directory to get the script across. The shared folder was configured correctly (Access: Full, Auto Mount: Yes) but simply didn't appear as a mapped drive or accessible path from inside the VM.

Ran Test-Path "C:\Program Files\Oracle\VirtualBox Guest Additions" and got False, Guest Additions had never been installed on this VM. Without them, there's no driver support for shared folders to mount against, regardless of how correctly the share itself is configured.

Fix
Attempted to install Guest Additions via the runtime Devices menu, but the menu bar wasn't accessible in this session. Worked around it by shutting the VM down and attaching VBoxGuestAdditions.iso as a second virtual optical drive through Settings > Storage instead, then booting back up and running VBoxWindowsAdditions.exe from the mounted CD drive.

The installer prompted a restart to complete. After reboot, re-ran the Test-Path check, this time returning True, and confirmed the shared folder was now accessible at \\VBOXSVR\Computer_application with the script file visible inside it.

Verification
Copied the script across from the now-working share and ran it as Administrator:

Copy-Item "\\VBOXSVR\Computer_application\Northgate-Diagnostics.ps1" -Destination "C:\Scripts\Northgate-Diagnostics.ps1"
.\Northgate-Diagnostics.ps1

Confirmed clean execution: system info gathered correctly, DNS resolution to northgateretail.local succeeded, Print Spooler confirmed running, and 110 System log errors/warnings pulled from the last 24 hours. The gateway check failed as expected, this VM's NAT Network configuration has no default gateway to reach, a known limitation of the lab network rather than a fault in the script. Cross-checked the log file itself with Get-Content and confirmed it matched the live console output exactly, including the full event log table.

Root Cause
VirtualBox Guest Additions were never installed on Win11-Client when the VM was first built. Shared folders depend on Guest Additions for driver support, so no amount of correct configuration on the share itself would have made it mount without them present.

Resolution

* Installed VirtualBox Guest Additions on Win11-Client via a second virtual optical drive, since the runtime Devices menu route wasn't available
* Confirmed shared folder access afterwards (\\VBOXSVR\Computer_application) before attempting the file copy again
* Successfully copied and ran Northgate-Diagnostics.ps1, verifying both console output and the resulting log file

Lessons Learned

* A correctly configured shared folder that still won't mount points at Guest Additions before anything else, worth checking Test-Path against the Guest Additions install directory early rather than re-checking the share settings repeatedly
* Guest Additions is worth installing as a standard step when first building any new VM, rather than only discovering the gap when a shared folder or clipboard feature is needed
* Verifying a script's output means checking the log file it produces, not just the console it printed to, the two should match, and confirming that catches any gap between what ran and what got recorded
